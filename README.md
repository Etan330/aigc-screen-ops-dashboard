# AIGC 互动大屏 · 运营数据看板

面向「AI 产品运营」岗位测评的后台看板原型。**全部数据为模拟数据**，不含任何真实用户隐私信息，也未接入任何真实大模型或后端服务。

看板覆盖四个运营视角：**活动效果 / AI 生成质量 / 内容审核 / 设备状态**，并内置由规则动态计算的**异常监控与定位**。

---

## 一、先看结论：这个看板能回答什么

| 运营问题 | 看哪里 |
| --- | --- |
| 活动效果好不好？ | 顶部 KPI 卡（参与人数、扫码转化率、分享转化率）+ 第 1 区「活动效果分析」 |
| AI 生成稳不稳？ | KPI 卡（生成成功率、平均生成时长）+ 第 2 区「AI 生成质量与内容审核」 |
| 异常发生在哪里？ | 第 4 区「异常监控与定位」，按规则 / 严重程度筛选，点击可下钻 |
| 影响有多大？ | 异常条目直接给出「实际值 / 阈值 / 样本量」，并按样本量下限过滤小样本误报 |
| 下一步做什么？ | 每条异常自带「待验证假设」与「运营建议与下一步排查方向」 |

## 三、在 macOS 上运行（不需要开发经验）

### 第 0 步：确认环境

打开「终端」（Terminal，可在「启动台 → 其他」里找到），逐行粘贴下面的命令并回车。

先确认电脑上已有 Node.js 与 Python：

```bash
node -v      # 需要 v18 或更高，例如 v22.22.2
python3 -V   # 需要 3.9 或更高，例如 3.13.12
```

如果提示 `command not found`，请先安装：

- Node.js：到 <https://nodejs.org> 下载 LTS 版本安装包，一路下一步即可。
- Python3：macOS 自带，若无则到 <https://www.python.org/downloads/macos/> 下载。

### 第 1 步：进入项目目录

```bash
cd ~/Desktop/ai数据看板
```

> 如果你的项目放在别的位置，把上面路径换成实际路径即可（也可以输入 `cd ` 后把文件夹直接拖进终端窗口）。

### 第 2 步：安装依赖

```bash
npm install
```

第一次执行大约需要 1-3 分钟，屏幕会滚动很多文字，属于正常现象。结束后会看到 `added xxx packages`。

### 第 3 步：启动看板

```bash
npm run dev
```

终端里会出现类似下面的提示：

```
VITE v5.4.21  ready in 500 ms
➜  Local:   http://localhost:5173/
```

### 第 4 步：打开看板

在浏览器（Chrome / Safari 均可）地址栏输入：

```
http://localhost:5173
```

回车即可看到看板。首次加载会读取约 10MB 事件级模拟数据，约 1-2 秒，期间显示加载动画。

**停止看板**：回到终端窗口，按 `Ctrl + C`。

## 四、如何重新生成模拟数据

数据已随项目提供（`public/data/` 目录）。如需重新生成（结果完全一致，因为随机种子固定为 `20261011`）：

```bash
python3 scripts/generate_mock_data.py
```

终端会输出各文件大小与记录数，例如：

```
written: .../public/data/mock_events.json  (10.00 MB)
=== 汇总 ===
{ "sites": 6, "devices": 12, "participations": 13529, ... }
```

刷新浏览器即可看到新数据（内容应与之前完全一致）。

## 五、如何验证主要功能（逐条可复现）

### 1. 筛选是否真的联动

1. 顶部「日期范围」依次点击 **今日 / 近 7 天 / 近 30 天**。
2. 观察：KPI 卡、趋势图、漏斗、点位明细、失败原因分布、异常列表**同步变化**；筛选栏底部「命中事件记录」数字随之改变。
3. 把「点位」切换为 **北京·朝阳大悦城**：所有图表收窄到该点位，异常列表只剩该点位相关条目。

### 2. 异常是否动态计算（不是写死的红标签）

1. 日期选 **近 30 天**、点位选 **全部点位**。
2. 在「异常监控与定位」中点击规则 **R1**，应能看到 **SITE-02（北京·朝阳大悦城）在 2026-10-02 ~ 10-05** 的多条生成成功率告警。
3. 点击其中一条打开详情抽屉，核对三处证据：
   - 「各设备生成成功率」：DEV-03 明显低于同点位 DEV-04；
   - 「失败原因分布」：以 **模型推理超时** 为主；
   - 「失败任务原始样例」：可看到具体 taskId / 时间 / 设备 / 原因。
4. 把点位切到 **北京·朝阳大悦城**，再点设备 **DEV-03** 打开设备详情：心跳时间线中 **2026-10-02 14:05-15:20 出现红色缺失段**。

### 3. 设备在线状态不被历史日期误导

1. 把日期切到 **2026-09-01 ~ 2026-09-05**（一个很早的区间）。
2. 设备监控中 **DEV-04、DEV-10 仍然显示离线**——因为在线判定只相对「数据基准时间 2026-10-11 20:00」，不随历史日期筛选变化。

### 4. 案例 A / 案例 B 一键复现

滚到第 5 区「运营决策演示案例」，点击卡片上的 **一键复现筛选** 按钮：

- 案例 A：自动筛选到 SITE-02 + 2026-10-02 ~ 10-05（生成失败率上升）。
- 案例 B：自动筛选到 SITE-06 + 2026-09-12 ~ 10-11（参与量高但扫码 / 分享低）。

> 补充：在默认的「近 30 天 + 全部点位」视图下，异常列表共 15 条：R1 × 5、R2 × 3、R3 × 4、R4 × 2、R5 × 1，严重 5 / 高 9 / 中 1。
> 其中 R1 有 1 条是基线噪声（成功率 86.5%，严重度仅为「高」），说明规则在阈值附近仍会受抽样波动影响，需要结合样本量与趋势判断；切到「近 7 天」只剩 1 条，说明筛选确实联动。

### 5. 空状态与分母为零

1. 自定义日期选择 **2026-08-13 ~ 2026-08-13**（数据首日，样本很小），观察 KPI 与图表；
2. 再把日期选择到数据范围之外的日期（浏览器日期选择器会限制在 `2026-08-13 ~ 2026-10-11` 之间，可先选一个几乎没有记录的点位 + 单日组合）；
3. 观察：图表显示「当前筛选条件下没有数据」，指标显示 `—`，**不会出现 NaN 或崩溃**。

## 六、异常规则（演示阈值，可修改）

| 规则 | 粒度 | 触发条件 |
| --- | --- | --- |
| R1 生成成功率 | 点位·日 | 成功率 < 90%，且当日已完成生成尝试 ≥ 20 次 |
| R2 平均生成时长 | 点位·日 | 平均时长 > 15s，且当日成功任务 ≥ 20 次 |
| R3 审核拒绝率 | 点位·日 | 拒绝率 > 10%，且当日已审核内容 ≥ 20 条 |
| R4 设备离线 | 设备·实时 | 最近心跳距基准时间 > 5 分钟（不随日期筛选变化） |
| R5 扫码转化异常（扩展） | 设备·区间 | 扫码转化率 < 大盘 50%，且该设备可扫码有效内容 ≥ 30 条 |

修改方式：打开 `src/lib/config.ts`，改 `THRESHOLDS` 里的数值并保存，页面会自动重新计算（开发服务器热更新）。页面上「当前生效的阈值」区域会同步显示新值。

## 七、数据里注入的 5 类异常（都有原始数据证据）

| 场景 | 位置 | 时间窗 | 证据 |
| --- | --- | --- | --- |
| 生成失败率上升 | SITE-02 / DEV-03 | 10-02 ~ 10-05 | DEV-03 失败率 42.4%（198 次尝试失败 84 次），失败原因以「模型推理超时」为主；同点位 DEV-04 成功率 97.0%；DEV-03 心跳 14:05-15:20 中断 |
| 平均生成时长变慢 | SITE-04（两台户外机） | 10-06 ~ 10-08 | `durationMs` 日均值 17.5s / 18.6s / 17.6s，基线约 5.6s |
| 审核拒绝率上升 | SITE-05 | 10-07 ~ 10-10 | 点位拒绝率 12.2%~17.6%；「奇幻光影」风格 60.4%，其余风格 0%~4.8%；该风格在活动期曝光权重 ×3 |
| 设备离线 | DEV-04 / DEV-10 | 基准时点 | 心跳数组在对应时点后无任何记录（45 分钟 / 3 小时 15 分钟） |
| 高参与低转化 | SITE-06 / DEV-12 | 09-12 ~ 10-11 | DEV-12 扫码率 7.5%，同点位 DEV-11 32.3%（大盘 31.1%） |

> 注意：看板把「可能的原因」明确标注为**待验证假设**，不把数据间接支持的判断表述为已确认根因。

## 九、技术栈

- React 18 + Vite 5 + TypeScript（strict 模式）
- Recharts 2（图表）、lucide-react（图标）
- 纯 CSS 设计系统（浅色背景、统一卡片与图表组件）
- Vitest（23 项自动化测试）
- 本地 JSON 模拟数据，无数据库、无登录、无真实 AI API

## 十、已知限制

- 事件文件约 10MB，首次加载约 1-2 秒；生产环境应改为服务端聚合接口。
- 设备心跳只保留最近 15 天，更早的「历史在线率」无法计算。
- 扫码后落地页的成功率没有模拟数据支撑，案例 B 中相关假设标注为「需服务端埋点验证」。
- 模拟数据基准时间固定为 `2026-10-11 20:00:00`（Asia/Shanghai），不是真实当前时间。
