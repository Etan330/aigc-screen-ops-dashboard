AIGC 互动大屏运营看板 · 指标口径说明

统计对象　全部指标从同一套事件级模拟数据派生（public/data/mock_events.json），任何图表、卡片、详情页均不写死结果，因此同一指标在不同页面数值必然一致。

时间归属　参与事件与生成任务按事件自身日期归属；内容、审核、扫码、分享统一归因到内容生成日，保证「生成成功 → 审核通过 → 扫码 → 分享」四步口径可比。

有效内容　生成成功 且 审核通过的内容 = 可扫码、可分享的内容；审核中与已拒绝不进入扫码 / 分享转化率的分母。

分母为零　所有比率返回「—」，不显示 0 或 NaN。

一、核心指标

指标定义计算口径（分子 / 分母与去重规则）运营意义指标异常时的行动
参与人数统计期内发起参与事件的去重用户数count(distinct userId)；跨点位重复用户只计一次活动拉新规模与点位吸引力下滑：查点位客流、活动物料、设备是否离线；上升但转化未升：先修转化链路，不要继续加量
AI 生成成功率成功生成占已完成生成尝试的比例成功任务数 /（成功 + 失败）；生成中不入分母技术链路健康度，< 90% 触发 R1按设备下钻定位故障机；按失败原因派单：超时 → 运维查网络与服务端，参数异常 → 前端查模板下发；必要时临时下线异常设备分流
扫码转化率至少扫码一次的有效内容占比去重扫码内容数 / 可扫码有效内容数；同一内容多次扫码只计一次内容是否真的被用户带走检查屏幕二维码的尺寸、位置、亮度与引导文案并做 A/B 对照；核对扫码后落地页加载成功率；核查成图质量
分享转化率至少成功分享一次的有效内容占比去重成功分享内容数 / 可分享有效内容数；分享失败不入分子内容传播与外溢效果优化分享话术与默认文案；对高分享风格加大曝光；低分享点位做现场引导改造
平均生成时长成功任务的生成耗时均值mean(durationMs)，仅含成功任务；同时看 P95 与超 15s 占比用户等待体验，> 15s 触发 R2P95 远高于均值：优化排队与长尾；全点位同步变慢：查点位网络 / 边缘节点；单台变慢：查该设备硬件
内容审核通过率通过占已完成审核内容的比例通过数 /（通过 + 拒绝）；待审核不入分母内容治理健康度，拒绝率 > 10% 触发 R3按风格定位：集中在单一风格则下线或调整该风格模板与提示词；全域上升则人工复核是否策略误杀，反馈审核策略侧
设备在线率最近 5 分钟内有有效心跳的设备占比心跳距基准时间 ≤ 5 分钟的设备数 / 设备总数；实时口径，不随日期筛选变化点位可用性，直接决定参与与生成量离线超 60 分钟：派单现场检修；同点位多台离线：按点位网络故障上报；恢复后复核心跳连续性与当日成功率

二、异常规则与阈值

阈值集中定义在 src/lib/config.ts，属于演示规则，修改后全站判定结果自动重算，页面底部同步展示当前取值。

规则粒度触发条件（含样本量下限）运营动作
R1 生成成功率点位·日< 90% 且当日已完成生成尝试 ≥ 20 次；< 80% 升级为「严重」下钻同点位各设备定位故障机，按失败原因分派给技术运维或前端
R2 平均生成时长点位·日> 15s 且当日成功任务 ≥ 20 次；> 25s 升级为「严重」对比同点位各设备与全网均值，区分点位级问题与服务端容量问题
R3 审核拒绝率点位·日> 10% 且当日已审核内容 ≥ 20 条；> 20% 升级为「严重」按创作风格与拒绝原因定位，调整模板或反馈给审核策略侧
R4 设备离线设备·实时最近心跳距基准时间 > 5 分钟；> 60 分钟升级为「严重」联系现场确认通电与网络；超过 1 小时派单检修
R5 扫码转化异常（扩展规则）设备·区间扫码转化率 < 大盘 50% 且可扫码有效内容 ≥ 30 条现场巡检二维码展示与引导文案，做 A/B 对照，并核对落地页加载

样本量下限的作用是避免小样本误报（例如当日只有 3 次尝试、失败 1 次就显示 66%）。

三、边界处理

情况处理方式
分母为 0返回「—」
生成中任务 / 待审核内容分别不进入成功率、审核通过率分母；内容不可扫码 / 分享
审核拒绝内容不进入转化率分母，单独统计拒绝原因
同一内容多次扫码 / 分享内容级去重，只计一次
分享失败不进入分享转化率分子，单独统计失败次数
跨点位重复用户全局去重只计一次，KPI 卡提示已去重人数
跨日期任务 / 空区间按事件自身日期归属；空区间显示空状态与「—」

四、口径红线

  1. 生成失败 ≠ 审核拒绝。 前者是技术链路问题（派单技术运维），后者是内容治理问题（反馈审核策略），分母、归因与责任人都不同，不得合并成「内容没出来」一个口径。
  2. 漏斗不混算。 用户层统计「去重人数」，内容层统计「内容条数」，两层分开呈现；人均任务数、单内容扫码次数等过程量单独列出，不进入转化率。
  3. 不把假设说成结论。 异常详情中的「可能的原因」一律标注为待验证假设，需结合设备日志、服务端监控或现场巡检验证。
